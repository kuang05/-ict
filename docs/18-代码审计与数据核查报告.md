## 一、数据核查（最高优先级：泄漏会让所有指标虚高）

### 1.1 外部数据与测试集是否重叠 → 无 ✅

| 检查项 | 方法 | 结果 |
|---|---|---|
| `pv_extra`（22789 张田间图）vs PlantDoc | 文件名 + **MD5** 双重比对 | 文件名重叠 0，**MD5 重叠 0** |

**结论**：外部田间数据与评测集完全无重叠，不构成泄漏。

### 1.2 PlantDoc 官方 train/test 划分 → **发现原图级重叠** ⚠️

用 MD5 逐张比对 train/val/test：

| 分裂对 | 重叠图像数 | 涉及文件 |
|---|---|---|
| train ∩ val | 0 | — |
| **train ∩ test** | **3** | `Tomato___Septoria_leaf_spot/i1055_c0,c1`、`Blueberry___healthy/i2048_c0` |
| **val ∩ test** | **5** | `Tomato___Tomato_Yellow_Leaf_Curl_Virus/i1269_c0~c4` |

**根因**：PlantDoc **官方** train.parquet 与 test.parquet 之间存在少量**同原图**样本
（同一张原图被同时放进了两个 split）。这是数据集自带问题，不是我们划分脚本的 bug
（`prepare_plantdoc.py` 的原图级划分逻辑本身正确，已验证 train∩val = 0）。

**影响**：8 张泄漏样本 / 452 张 test = **1.77%**，理论上可使 test top1 虚高 ≤ 0.66pp。

**处置**：新建 **`~/data/pd_v3`**（硬链接副本，仅占 480K），从中移除这 8 张：
* train 6723 → **6720**
* val 1719 → **1714**
* test 452（保持不变）
* 复验：train∩test = val∩test = train∩val = **0** ✅

**此后所有训练与评测均使用 pd_v3**，模型不再接触泄漏样本，指标干净。

## 二、代码审计：发现并修复 9 个问题

| # | 文件 | 问题 | 严重度 | 修复 |
|---|---|---|---|---|
| 1 | `eval_v3.py` | `load_state_dict(strict=False)` **静默加载**，权重没加载上却照样跑出指标（v2 时代曾因此得到 top1=4.2% 的荒谬结果） | **高** | 缺失键直接 `SystemExit`；多余键提示但放行 |
| 2 | `train_hier.py` `train_field_v3.py` | `--workers 0` 时 `prefetch_factor=6` → **ValueError 崩溃**（PyTorch 要求多进程才允许该参数）**← 自检抓到** | **高** | `prefetch_factor = 6 if workers>0 else None` |
| 3 | `train_hier.py` `train_field_v3.py` | npu autocast 传 `bfloat16` → 910B **只支持 float16**，被 torch 静默禁用 → 实际 FP32 训练，白丢约一倍速度 | 中高 | 改 `float16` + `torch.npu.amp.GradScaler()` |
| 4 | `train_hier.py` | DataLoader `shuffle=True` **无 generator** → 每次运行数据顺序不同，**不可复现**（比赛红线） | 中高 | 加 `torch.Generator().manual_seed(42)` |
| 5 | `export_onnx.py` | 层次化路径下过滤 `crop_head.*`，但 `NetV4` 本身含 crop_head → `missing=2` 加载失败 **← 自检抓到** | 中高 | 层次化时全量加载；单头时才过滤 |
| 6 | `export_onnx.py` | `Net(...)` 未传 `pretrained=False` → 无谓下载 ImageNet 权重 | 中 | 显式 `pretrained=False` |
| 7 | `eval_hier.py` | 未同步 `eval_v3.C2I` 标签空间 → ckpt 类序不一致时会错标 | 中 | `ev.C2I.clear()/update(ckpt classes)` |
| 8 | `compute_hr.py` | 重复的 `resnet101` 分支（死代码）+ 未定义的 `n_cls`；timm 双头会 strict 加载失败 | 中 | 重写 `load_net`，只支持单头 resnet，timm/双头明确报错并指向 `eval_hier.py` |
| 9 | `--init` 微调（上一轮） | 键带 `backbone.` 前缀未剥离，`strict=False` 静默吞掉 → 微调实际从 ImageNet 重来 | 高 | 剥离前缀 + 打印不匹配数 |

## 三、模型方法分析：EMA + MixUp 被证伪（重要）

### 3.1 实验结果

| 版本 | 骨干 | 分辨率 | 轮数 | MixUp | EMA | PDval | **test top1** |
|---|---|---|---|---|---|---|---|
| **v11（基线）** | R101 | 224 | 20 | ✗ | ✗ | 0.7086 | **67.92%** |
| v14 | R101 | 288 | 20 | ✗ | ✗ | 0.7068 | 66.81% |
| v13 | R50 | 224 | 40 | ✓ | ✓ | 0.6981 | 64.38% |
| **v15** | R101 | 224 | 30 | ✓ | ✓ | 0.7039 | **61.28%** |

### 3.2 结论

* **v15 的 PDval（0.7039）只比 v11（0.7086）低 0.5pp，但 test top1 低了 6.6pp** ——
  这是典型的**验证集过拟合 + 泛化退化**，而不是"训练不足"。
* 分解 v15 的指标：crop_acc 82.08%（v11 86.73%）、disease|crop正确 74.66%（v11 78.32%）
  —— **全面退化**，说明不是某一类的问题，而是整体表征质量下降。
* **v13 与 v15 是两个独立实验，都用了 EMA+MixUp，都退化** → 强证据。
* **最可疑的机制**：EMA 实现里 `buffers` 被**直接复制**（`b_e.copy_(b)`）而非做 EMA，
  导致"EMA 平滑后的权重"配"当前步的 BN running stats" —— **权重与 BN 统计量不匹配**，
  这是 EMA 的经典陷阱，会显著损害泛化。

### 3.3 处置

**后续所有实验改用干净配方**（与 v11 完全一致）：
```
R101@224, 20ep, batch 64, lr 3e-4, pv_per_class 600, pd_repeat 3
无 MixUp、无 EMA、MixStyle 外挂 p=0.5
```
这样与 v11 的**唯一差异**就是被测变量（层次化双头 / 现代骨干），归因干净。
