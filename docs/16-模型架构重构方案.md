## 一、比赛规则对"模型"的真实要求（把四维度翻译成模型语言）

| 评分维度 | 对模型的具体要求 | 当前状态 | 缺口 |
|---|---|---|---|
| **创新性**（核心区分度） | 跨域泛化是真技术贡献，必须**持续量化提升** | 28.3% → 66.81%（v3）→ 67.92%（v11） | 提升幅度进入平台期，需要**新机制**而非调参 |

## 二、当前模型的根本缺陷（为什么调参到顶了）

v3~v13 都是**单一 27 类 flat softmax**。它的结构性缺陷：

1. **作物-病害耦合**：作物判错 → 病害必错。而 flat 模型把"区分番茄/马铃薯"（粗）和
   "区分早疫/晚疫"（细）塞进同一个 softmax，特征被细粒度病害主导，
   **作物级判别力反而不够**。实测 crop_acc 只有 86.7%，成为 top1 的硬上限。
2. **没有"不确定"概念**：softmax 永远输出一个类，没有拒识机制。
   对"筛查+决策支持"定位而言，**低置信样本应当拒识转人工**，而不是硬给一个可能致命的错判。
3. **只有分类，没有严重度**：农事决策需要"病得多重"，而分类器只答"是什么病"。
   （RDD/PlantDoc 相关论文均把 severity 列为未解决问题。）

## 三、重构方案：层次化多任务 + 层次融合 + 高危守门

### 3.1 架构（`model/train_hier.py`）

```
        ┌──────────────────────────────┐
        │  ResNet101 backbone (MixStyle 外挂) │
        └───────────────┬──────────────┘
                        │ features
          ┌─────────────┴─────────────┐
          ▼                           ▼
   病害头 (27 类)               作物头 (13 类)
   = backbone.fc.*            = crop_head.*
   ← 主任务                    ← 辅助任务
```

损失：`L = CE_disease(类别权重 + 高危加权 + label_smoothing) + λ·CE_crop`（λ=0.3）

**设计要点**：病害头刻意仍放在 `backbone.fc`，因此 **state_dict 键与 v3 完全兼容**，
v3 的评测脚本可直接评测 v4 病害头（`crop_head.*` 被自动忽略）——工程上零破坏。

### 3.2 推理（`model/eval_hier.py`）

**层次融合**：

```
p_final(class) ∝ p_disease(class) · p_crop(crop_of(class))^α
```

α>0 时用作物先验抑制**跨作物误判**（如"番茄晚疫 → 马铃薯晚疫"是 v3 高频混淆）。
α 在 **PlantDoc val** 上选（最大化 val top1），在 test 上报告 —— 不碰测试集。

**高危守门**：置信度 `max(p_final) < τ` 的样本拒识转人工，
报告"拒识率 ↔ 高危漏诊率"曲线，把"筛查辅助"定位变成**可量化、可答辩**的设计。

### 3.3 为什么这是"根本性"重构而非调参

| | v3~v16（调参） | v4-hier（重构） |
|---|---|---|
| 输出空间 | 单一 flat 27 类 | 层次：作物 ⊗ 病害 |
| 监督信号 | 只有病害标签 | 病害 + 作物**双监督** |
| 推理 | argmax | 层次融合（作物先验） |
| 不确定 | 无 | **拒识守门** |
| 优化目标 | top1 | top1 + **高危漏诊率** |
