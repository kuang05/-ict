## 一、战略级发现：我们选了最拥挤的赛道

第十一届三道赛题（北工大/大连理工/北京物资学院三源一致）：

| 赛题 | 官方命题 | 竞争判断 |
|---|---|---|
| **赛题1** | 基于华为云产品打造 AI 创新应用 | **自由度最高＝竞争最激烈，评委见遍套路；无平台护栏，纯拼作品力** |
| 赛题2 | 基于华为云 **AgentArts** 智能体开发平台的 Agent 设计和应用 | 上一届同平台赛题（病理问答）已有成功路线可抄，模仿者会多 |
| **赛题3** | 基于华为 **ModelEngine Nexent** 打造**可进化决策智能体** | **官方定义未公开、无辅导视频、多数队观望＝红利期** |

禾医现在报的是**赛题1**，而文档 5.4 给的匹配度是 ★★（需大改）。

但禾医的智能体层——**诊断 → 决策（处置方案/高危升级）→ 执行反馈（复诊监测）→ 进化（知识库更新）**
——恰恰是**赛题3"可进化决策智能体"的教科书式闭环**，匹配度 ★★★★。

> 往届规律第4条：华为栈绑定逐届加深
> 8届 ModelArts+IoT+Astro → 9届 MindSpore/昇腾云 → 10届 ModelEngine/昇腾NPU
> → **11届 AgentArts / Nexent**。**平台型赛题是官方主推的新增长点。**

**建议**：主攻赛题3（Nexent 可进化决策智能体），赛题2（AgentArts）用同一套资产作备份。
风险：赛题3官方定义未公开，需盯通知——但也正因如此竞争者最少。

## 二、关键：华为栈深度绑定 ≠ 必须有昇腾硬件

这是最容易误解的一点。往届获奖作品的华为栈绑定有**多条路径**：

| 路径 | 代表作品 | 是否需要昇腾硬件 |
|---|---|---|
| ModelArts 训练 + IoTDA + Astro 大屏 | 同济"航济"（特等） | 否（云服务） |
| **华为云 IoT + OpenHarmony** | 厦大"声域领航"（国一、全球三等） | **否，且未用 ModelArts/昇腾** |
| 昇腾910B / 310B4 部署 | ABU ParaVision、华南师大 MindAligner | 是 |
| **Nexent / AgentArts 平台原生开发** | 本届赛题2/3 | **否** |

> 厦大案例说明：**非昇腾路线也能拿国一**。华为栈绑定考的是"用了华为的什么、
> 用得多深"，昇腾只是其中一种，且是最贵的一种。

### Nexent 是开源的，今天就能跑

- 仓库：`github.com/ModelEngine-Group/nexent`（≈5.9k star，**MIT**）
- 一键部署：`git clone … && cd nexent && bash deploy.sh docker`（**4核8G 起**）
- 能力：零代码生成智能体、**A2A 协议多智能体协作**、双层记忆、
  知识库（20+格式）、**MCP 工具生态**、知识溯源、**agent 版本管理与回滚**

**这台 AMD 云服务器（128核/503GB）完全够跑 Nexent。**

### 禾医迁到 Nexent 的三步（不需昇腾）

1. **推理引擎封装为 MCP Server**
   - 注意：第三方实测 Nexent **仅支持 SSE 协议 MCP**，不要用 stdio
   - 把 `model/infer.py` 包成 MCP 工具：`diagnose_leaf(image) -> {top3, 置信度, 特征}`
2. **知识库导入**：`data/knowledge/diseases.json` 迁入 Nexent 知识库，
   直接复用其**知识溯源**能力（正好强化我们"防幻觉可溯源"的叙事）
3. **Agent 版本管理**：用 Nexent 的版本管理/回滚讲"进化"

### AgentArts（备份路线）
- 文档入口 support.huaweicloud.com/agentarts；仅贵安区域
- **开源版 openJiuwen 已上线**（与企业版内核同源度 90%+）→ **本地练手不依赖公测资格**
- 内置 300+ 工具、预置评估器（**正确性/幻觉/工具调用质量**）
  ——"幻觉评估器"正好可以量化我们防幻觉设计的效果

## 三、"可进化"闭环（赛题3核心考点，禾医差最后一步）

禾医已有"复诊监测"，但缺**反馈闭环**。补齐三件套：

| 件套 | 做法 | 讲给评委的故事 |
|---|---|---|
| ① 反馈采集 | 复诊/误诊反馈表单 → 入库 | 用户纠正成为系统输入 |
| ② 策略版本化 | 知识库与处置策略**版本管理 + 回滚**（Nexent 原生能力） | "进化"是可控、可追溯的 |
| ③ 自动回归 | 固定评测集 + 回归脚本，每次进化跑一遍并量化 | 借鉴"64%→87%"迭代叙事 |

**我们其实已经有现成的迭代故事**：
28.3% → 32.5% → 56.6% → **66.81%**，四阶段全有日志和 JSON 存档，
这正是一条完整的"进化曲线"，直接可以当赛题3的核心证据。
