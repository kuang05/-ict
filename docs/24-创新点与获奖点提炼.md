# 24 · 创新点与获奖点提炼（2026-10-17）

> 目的：把"我们做了什么"提炼成评委能记住的"我们做对了什么"。
> 原则：**区分真创新与包装**——凡不能用数字或机制证明的，一律不写进答辩主线。

---

## 一、真创新（有机制、有数字、可复跑）

### 1. 假药拒绝：敢对"特效药"说不（最独特）

**机制**：输入侧护栏——从问题中提取"治/喷/打"前的动作主体，排除病害后缀（病/毒/虫/螨）
后若不在知识库药名词表 → **拒绝给出用法与配比**，固定回复提示核实登记信息。

**为什么是真创新**：市面上所有农业 AI 都在"回答问题"，没有一个敢在**用户假设错误时拒绝作答**。
"神灭灵""绝病清""绿盾1000号"这类编造药名在短视频/流动推销里泛滥，农户受骗后轻则白花钱、
重则错过防治窗口。**AI 不为未核实的农药背书**——这是一个真实存在但没人解决的安全问题。

**数字**：假药陷阱 **6/6 拦截**，正常问病 **0/4 误伤**（`tests/test_agent.py::test_anti_hallucination` 可复跑）。

### 2. 幻觉→知识库审计：把错误变成进化信号（最巧）

**机制**：LLM 每次"加戏"（补充知识库外的药名/温度/天数）都被护栏记录；
`evaluation/kb_gap_audit.py` 把这些信号按病害归组，产出 **KB 补充候选清单**（实测 59 项/15 病害）；
经《中国农药信息网》登记核对 + 权威佐证后入库，KB 版本 +1，回归复跑确认。

**为什么是真创新**：常规做法是"把幻觉当 bug 消灭"；我们把幻觉当**知识库的体检报告**——
模型知道而知识库不知道的，正是知识库的缺口。这形成"使用→暴露缺口→补全→更准"的正循环，
**这就是"进化层"最硬的实证**，而不是一句口号。

**数字**：59 候选 / 15 病害（`docs/KB补充候选清单.md`，一条命令可重跑）。

### 3. 确定性校验当裁判：我们连 LLM 裁判都不信（最硬）

**机制**：输出侧确定性事实过滤器（数字+药名必须落地于给定事实，违规整段回退模板）；
评测主指标改为**确定性校验通过率**，LLM-Judge 降为辅助信号。

**为什么是真创新**：实测发现 LLM-Judge **不可复现**——同一份代码连续两次运行，
WRONG 数 3→10（7 个用例翻转）。这证明"用 LLM 当裁判"本身不可靠。
在"可信 AI"这个赛道上，**连评测裁判都要求可复现**，是方法论层面的降维打击。

**数字**：确定性校验 **44/44 PASS（100%）**；四轮迭代 WRONG 28→23→9→6（Judge）/ 主指标 100%。

### 4. 守门曲线：把"不知道"变成可量化的安全（最贴农事）

**机制**：置信度阈值守门——低于 τ 的样本转人工而非硬猜；τ=0.6 时
"病叶判成健康"（最危险错误）从 **10.09% → 0.00%**。

**为什么是真创新**：所有识病 App 都在追求"更高的准确率"；农事决策真正怕的是
**"把病叶说成健康"**（延误防治=绝收）。我们明确把"承认不确定"作为产品原则，
并用曲线把代价讲清楚（拒绝率 vs 漏诊率的权衡）——这是**决策思维**而非识别思维。

## 三、获奖点（评委能记住的五句话）

1. **"我们连裁判都不信"** —— 确定性校验当主指标，还实测证明了 LLM 裁判不可复现（3→10 翻转）
2. **"敢说不知道"** —— 守门曲线 10.09%→0.00%，假药陷阱 6/6 拒绝
3. **"幻觉是知识库的体检报告"** —— 59 项候选反哺知识库，验证后入库
4. **"28.3% → 69.69%，每个数字一条命令可复跑"** —— 对标文献 54.24%，无泄漏协议
5. **"四轮迭代，每轮一个真问题"** —— 不是一次做对，而是持续变好（进化层的自证）

> 这五句话对应五维：1→创新性/技术复合性，2→社会效益，3→创新性，4→创新性/系统复杂性，5→功能完备性。
