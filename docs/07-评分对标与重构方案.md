## 三、五个决定档次的差距（按严重性排序）

### 差距 1（致命）：华为技术栈是"纸面"的，不是"跑过的"

赛题二全名是「**基于华为云 AgentArts 智能体开发平台的 Agent 设计和应用**」——
华为云/AgentArts 的使用是**硬性要求**，
不是加分项。目前证据链是断的：

| 声称 | 实际证据 |
|---|---|
| "昇思 MindSpore 主训练栈" | `train_mindspore.py` 存在，但 device_target 靠 `if ASCEND_HOME_PATH` 分支切换，**从未在昇腾执行过** |
| "昇腾910训练 / 310部署OM" | 仅注释里一句话，无 ATC 转换产物 |
| "ModelArts 训练" | 实际训练跑在 **AMD Radeon (ROCm 7.2.4) + PyTorch 2.10** |
| "OBS 存储 / MaaS 大模型 / IoTDA" | 文档中列为"规划"，无调用记录 |

**评委一问"昇腾在哪、华为云调用记录呢"，目前答不上来。**
这一项直接决定能否进入高分段。

### 差距 2（高）：最大的创新成果没写进方案文档

`docs/01-作品设计方案.md` 仍停留在 v1 阶段：

- 第 11 节写的是「田间零样本 **28.3% / 32.5%**」，作为"局限性"诚实披露
- 而我们已经做到 **66.81%**（跨域 +34.5 pp，v3 模型，test 452 裁叶 + TTA）

**故事完全变了**：从"我们承认田间只有28%"变成"我们把田间从28%拉到66.8%，
并超过同任务论文（Sensors 2026 少样本 54%）"。前者暴露短板，后者是原创技术贡献。
这个数字必须在方案文档里作为**第一创新点**呈现。

### 差距 3（高）：「端-云-边三级」只有"云"

架构图画了端/边，实际只有云端 FastAPI。
前端 134 行单页，没有鸿蒙 App、没有小程序、没有端侧推理。
"永远有输出"的降级引擎是设计，但**没有端侧载体可以演示**。

### 差距 4（中）：缺一手真实数据

往届特等奖几乎都有现场采集的一手数据（同济航济、华中师大 Atlas Guardian——团队自述高品质自采数据集为获奖关键）。
我们 100% 依赖公开数据集，评委可能质疑"真实场景验证过吗"。

### 差距 5（中）：讲述方式不对

现在对外讲的是「PlantVillage **99.31%**」。
**这个数字在评委眼里没有区分度**——PlantVillage 上谁都能到 99%，
它恰恰掩盖了真正有价值的工作（跨域泛化）。
应学 NeckGuard：**每个创新点都量化**。

## 四、重构方案（按优先级）

### P0 · 把华为技术栈做实（决定能否进高分段）

> 前提：需要昇腾算力。见第五节决策项。

1. **昇腾 NPU 真跑一次训练**
   - 路径 A：华为云 ModelArts（昇腾910）跑 `train_mindspore.py`，
     保留控制台截图、训练日志、作业 ID 作为评分证据
   - 路径 B：昇腾社区 / 学校昇腾实验室
2. **模型转 OM**（昇腾310 边缘部署）
   - PyTorch → ONNX → ATC → `.om`，产出真实转换产物与推理耗时对比
   - 这一步最能体现"端-边-云"和昇腾深度
3. **盘古 / MaaS 真实调用**
   - 智能体接华为云 MaaS，保留调用日志，**真正体现"事实-语言"分层**
4. **ModelArts / OBS 实际使用**
   - 数据集与模型工件上传 OBS，训练作业提交 ModelArts，留痕

产出物：`docs/08-昇腾与华为云落地证据.md`（截图 + 日志 + 作业ID + 耗时对比）

### P1 · 重写方案文档，把跨域泛化讲成第一创新点

- 第一创新点改为：**「实验室→田间」跨域泛化，28.3% → 66.81%（+34.5 pp）**
  - 方法：MixStyle 特征层域泛化（CVPR 2021）+ 27类输出空间 + 目标域监督 + 类别平衡
  - 对比：同任务论文 *Sensors* 2026 少样本 54.24%，本作品全监督 **66.81%**
- 第二创新点：防幻觉智能体（对齐本届 Agent 考察点）
- 第三创新点：端-边-云三级推理 + 降级兜底
- **对外表述改为**：「PlantVillage 99.31%，**PlantDoc 真实田间 66.81%**」
  —— 不再主推 99.31% 那个没有区分度的数字

### P2 · 补一手真实数据（往届特等奖共性）

- 采集本地真实作物叶片照片（目标 100–300 张，覆盖 5–8 种常见作物/病害）
- 来源：学校农场/周边农田/同学家乡，**手机拍摄即可**（真实场景正是田间复杂背景）
- 用途：作为"真实场景独立验证集"，报告模型在这些照片上的表现
- 即便只有 100 张，"我们自己去田里拍了"这个事实本身就是加分项

### P3 · 端侧闭环（补齐"端-边"）

- 优先级：鸿蒙 ArkTS + MindSpore Lite > 微信小程序 > 纯 Web
- 最低可行：把现有 Web 前端打包成可在手机浏览器直接用的 PWA，
  现场用手机演示拍照诊断（**可现场演示**是完成度的关键）

### P4 · 量化商业与社会效益

- 单机成本、单次诊断耗时、相对人工植保员的效率提升
- 减药潜力：按"对症施药"估算农药减量百分比（需引用农技文献）
- 给出可落地的推广路径（合作社 / 农资店 / 农技推广站）
