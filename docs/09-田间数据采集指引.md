# 禾医 · 田间真实数据采集指引

> 为什么要做：往届特等奖作品几乎都有**一手真实数据**（同济去航空发动机实验室
> 采叶片、地大进岩矿标本库拍 9000+ 张）。评委明确认可的亮点是
> "**真问题 × 真数据**"。公开数据集（PlantVillage/PlantDoc）只能证明方法有效，
> **自己拍的照片才能证明"这真的是我们身边的问题"**。

---

## 一、拍什么（按优先级）

### 目标作物（与 PlantDoc 的 13 类对齐，模型认识这些）
番茄、玉米、马铃薯、黄瓜、辣椒、葡萄、苹果、樱桃、桃、草莓、南瓜、大豆、蓝莓

**最容易找到、最有价值的**：番茄、玉米、马铃薯、黄瓜、辣椒（校园/菜地/家里阳台都有）

### 优先拍的病害（高危优先，这些最能说明问题）

| 作物 | 病害 | 为什么优先 |
|---|---|---|
| 番茄/马铃薯 | **晚疫病** | 3~7 天毁田，最危险，也是我们漏诊率最高的 |
| 番茄 | **黄化曲叶病毒 / 花叶病毒** | 无特效药，只能拔除 |
| 番茄 | 早疫病、叶霉病、细菌性斑点病 | 常见且易与其他病混淆 |
| 玉米 | **大斑病**、锈病 | 流行性强 |
| 黄瓜/南瓜 | 白粉病、霜霉病 | 极常见 |
| 葡萄 | 黑腐病、轮斑病 | 果园常见 |
| 辣椒 | 细菌性斑点病 | 常见 |

### **别忘了拍健康叶片！**（很重要）

每类作物至少拍 5~10 张**健康叶片**。原因：模型最大的危险不是"认错病"，
而是"把病叶判成健康"（漏诊）。有健康样本才能校准这个边界。

---

## 二、怎么拍（手机就够，注意这 6 点）

1. **自然光**，避免正午顶光直射和闪光灯（反光会让病斑失真）
2. **距离 20~40 cm**，让叶片占画面 1/2 以上
3. **每株拍 3 张**：
   - ① 病斑**特写**（看清颜色/形状/边缘）
   - ② 叶片**全貌**（看病斑分布）
   - ③ **整株 + 背景**（保留真实田间环境，**不要刻意虚化背景**）
4. **保留真实背景**——杂乱背景正是田间场景的特征，也是模型最需要学习的
5. **正反面都拍**——有些病害（如霜霉病）背面特征更明显
6. **同一个地方多拍几种**——同一块地的不同植株、不同发病程度（初期/中期/后期）

> ⚠️ **不要**用网上的图、不要用滤镜、不要摆拍成实验室白底——
> 那样就失去"真实场景"的价值了。

---

## 三、拍多少

| 阶段 | 数量 | 说明 |
|---|---|---|
| 最低可用 | **100 张** | 能做独立验证集，写进申请表 |
| 推荐 | **300 张** | 5~8 类病害 × 20~30 张 + 健康样本 |
| 理想 | 500+ | 可分出微调集与测试集 |

**别被数量吓到**——100 张手机照片，一个下午就能拍完。

## 四、怎么整理和交付

### 命名规范

```
作物_病害_序号.jpg
```

例如：
```
tomato_late_blight_001.jpg
tomato_late_blight_002.jpg
tomato_healthy_001.jpg
corn_northern_leaf_blight_001.jpg
```

### 存放位置

```
C:\Users\27740\Desktop\华为ICT\参赛作品-禾医\he-yi\data\field_captured\
├── tomato_late_blight\
│   ├── tomato_late_blight_001.jpg
│   └── ...
├── tomato_healthy\
└── corn_northern_leaf_blight\
```

（按**病害名建子文件夹**最省事，模型评测脚本能直接按文件夹读取）

### 同时记一个清单（很重要）

用手机备忘录或 txt 记下：

| 文件/批次 | 作物 | 疑似病害 | 拍摄地点 | 日期 | 备注 |
|---|---|---|---|---|---|
| tomato_001~020 | 番茄 | 晚疫病 | 学校菜地 | 10-05 | 连续阴雨后 |

**这个清单本身就是"真问题"的证据**——答辩时可以说
"这是我们在 XX 地实际发现的病例"。

## 五、拍完之后我做什么

1. 用这 100~300 张照片做**独立验证集**（不参与训练），测模型在**你自己的真实场景**上的表现
2. 出一份 `真实场景验证报告`：各类准确率 + 高危漏诊率 + 与 PlantDoc 的对比
3. 若效果不理想，用这批数据做**少量微调**（文献显示 200~500 张可恢复大部分损失）
4. 结果直接写进申请表和答辩 PPT——**"我们的模型在我们自己拍的照片上达到 XX%"**
   这句话的分量，远超"公开数据集上 99%"

---

## 六、如果实在拍不到

备选方案（按优先级）：
1. **问同学/家人要**——谁家有菜地、阳台种菜、老家农村，都能拍
2. **周边公园/校园绿化**——观赏植物也有病害，但要注意类别匹配
3. **农资店/种植户**——去当地农资店问问，他们天天接触病叶
4. **实在不行**：用 PlantDoc 的图片做"准真实"验证，但**必须在文档中如实标注来源**，
   不可声称是自采数据（诚实是底线，评委也会问细节）

## 七、标注规范与工具链（2026-10-16 补充）

### 7.1 标注 = 分文件夹 + 一遍人工复核

自采数据是**分类任务**（不是检测），"打标签"= 把照片放进正确的病害文件夹 + 至少一遍交叉复核：

1. 拍摄时或当晚就按 `作物_病害` 建子文件夹归档（见命名规范）
2. **复核一遍**：特别是"看着像但分不清"的（早疫病 vs 晚疫病、细菌性斑点 vs 叶霉病）——拿不准的单独放 `unsure/` 文件夹，找植保站/老师确认，**宁缺毋滥**（错标一张污染整个类的可信度）
3. 健康叶片务必单独成类（`tomato_healthy` 等）

### 7.2 入库一条命令（去重/标准化/登记/切分全自动）

```bash
# 干跑：先看文件夹映射和数量对不对（未知名会报错等待人工确认）
python scripts/ingest_field_data.py --src "data/field_raw" --out "data/field_captured" --dry-run

# 正式入库：去重 → 去EXIF → 长边封顶1600px → 按模型27类名重组 → 生成 registry.json
python scripts/ingest_field_data.py --src "data/field_raw" --out "data/field_captured"

# 可选：按 8:2 切出独立验证集（真实场景评测用，不参与任何训练）
python scripts/ingest_field_data.py --src "data/field_raw" --out "data/field_captured" --split 0.2
```

产出结构（与 `pd_v3/test_clean` 同构，评测脚本可直接读）：

```
data/field_captured/
├── Tomato___Late_blight/   tomato_late_blight_a1b2c3d4.jpg ...
├── Tomato___healthy/       ...
├── Corn_(maize)___Northern_Leaf_Blight/ ...
└── registry.json           ← 每张图的来源/MD5/标签全记录（答辩证据）
```

**registry.json 就是"真数据背书"的凭证**：答辩被问"数据哪来的"，直接展示每张图的拍摄文件夹、MD5、入库时间。

### 7.3 入库后立刻能做的三件事

1. **真实场景评测**：`model/eval_hier.py --data data/field_captured --val ...` → 出一份"我们的模型在我们自己拍的照片上 XX%"的报告（这句话的分量远超公开集 99%）
2. **少量微调**：文献显示 200~500 张自采图可恢复大部分跨域损失（用 `--init best_v11.pth` 微调，低学习率）
3. **数据故事升级**：申请表/PPT 加上"自采 N 张真实田间数据 + 独立验证集"——对齐往届特等奖（同济/地大/Atlas Guardian）的同一叙事

## 九、联系路径与话术（2026-10-16 补充）

### 9.1 按成功率排序的四个渠道

1. **校内试验田/农学院基地**（成功率最高）：本校农学/植保学院通常有实验田和标本——"学生比赛项目想拍点真实病害照片"，学院老师一般愿意支持，还可能提供病害鉴定（= 免费专家标注）
2. **当地植保站**：打电话/上门说明来意，争取 30 分钟实地拍摄；植保站有历年病害标本和最新病例
3. **农资店/种植户**：农资店天天接触带病叶片求诊的农户——拍完请店主/农户口头确认病害名（口头确认也记入 registry 备注）
4. **自家/亲戚菜地阳台**：番茄辣椒最稳，一个下午能拍 100 张

### 9.2 一句话话术

> "我们是参加华为 ICT 大赛的学生团队，做农作物病害 AI 诊断，需要**真实田间**的病害照片做模型验证。拍照只用几分钟，不碰您的作物。您看到的病叶如果能帮我们确认一下是什么病，就太感谢了。"

### 9.3 每张照片背后都记三件事（registry 的备注列）

拍摄地点（哪块田/哪个棚）｜ 疑似病害（谁确认的：自己看/店主/植保员）｜ 天气背景（如"连续阴雨后"——晚疫病高发的环境证据）

这三列信息在答辩时全部可讲：**"这是我们在 XX 棚实际发现的晚疫病，雨后第三天，经店主确认"**——这就是特等奖作品的"真数据"质感。
