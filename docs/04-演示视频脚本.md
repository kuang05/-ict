# 演示视频录制脚本（3~4 分钟，1080p，配套字幕）

> 工具：OBS Studio 录屏 + 剪映加字幕；语速平缓，每个环节留操作停顿。
> **2026-10-16 重写**：① 口播数字全部替换为本地实测值；② 语言层改为 AMD LLMGateway
> （DeepSeek-V4-Flash 文本 + V4.1-Flash 视觉，本地对照实现；AgentArts 平台部署另录）；
> ③ 演示动线按“识别→决策→守门→进化”主线重排（新增镜头 4 守门、镜头 6 进化）。
> 启动命令与依赖陷阱见本仓库 README 第三节（.env.example 填 Key 即可）。

## 镜头1：开场（15s）
画面：PPT/P1 封面或应用首页
口播：
"这是「禾医」——**可进化的农事决策智能体**，参加第十一届华为 ICT 大赛创新赛，
基于华为云 AgentArts 平台构建；识别底座在昇腾 910B 上用 PyTorch + torch_npu 训练，
经 ATC 转为 Ascend310B4 端侧 OM；语言层接入 AMD LLMGateway 的 DeepSeek 大模型。
它要回答的不是'这是什么病'，而是'那该怎么办'、'没把握时怎么办'、'下次怎么更准'。"

## 镜头2：痛点引入（20s）
画面：晚疫病毁田照片/新闻截图 → 切到"通用大模型幻觉回答"截图
口播：
"晚疫病这类暴发性病害三到七天就能毁掉整棚番茄；而直接问通用大模型'打什么药'，
它可能编造不存在的农药——农业生产中，幻觉就是事故。
所以我们把系统设计成：**识别只是感官，决策才是价值**。"

## 镜头3：诊断主链路·决策层（45s）
画面：应用首页 → 上传晚疫病叶片照片 → 点击诊断 → 结果页滚动展示
口播：
"上传一张感病叶片，秒级返回：番茄晚疫病，置信度 87.5%——这是 CPU 端 TTA 实测值。
下方是智能体生成的四段式报告：典型症状、发病条件、立即处置、农事预防，
由 AMD DeepSeek 大模型润色成农户听得懂的话——**但它只负责语言组织，
事实全部来自内置植保知识库，每个用药名称都可溯源，零幻觉**。
请注意这条红色升级卡——晚疫病是暴发性病害，系统自动提示隔离病株、联系当地植保站。"

## 镜头4：守门层（30s）
画面：上传一张“看着像但说不清”的模糊/遮挡叶片 → 展示低置信提示
口播：
"这是禾医最不一样的地方：**当模型没把握时，它不猜**。
低置信样本自动转入人工复核通道，而不是硬给一个可能错误的病名。
在我们的评测中，这套置信度守门把'把病叶判成健康'的最危险错误
从 10.1% 压到了零——对农药决策来说，承认不确定，比自信地犯错值钱得多。"

## 镜头5：对照与问答（35s）
画面：上传健康叶片 → 显示健康、无升级卡 → 问答框输入“番茄晚疫病初期怎么识别？”
口播：
"换一张健康叶片，识别为健康，无误报。
农事问答智能体支持自然语言提问，回答基于知识库检索生成，并标注引用条目——
这是检索增强，不是凭记忆作答。"

## 镜头6：进化层（30s）
画面：诊断记录/反馈入口（复诊、误诊反馈）→ 回到记录列表
口播：
"每一次诊断和每一次用户反馈，都会沉淀进系统的数据通道：
复诊对比让效果可验证，误诊反馈回流成为下一版模型的训练素材。
**这个系统会越用越准——这才是它和'拍照识病工具'的本质区别。**"

## 镜头7：技术架构与收尾（30s）
画面：架构图 → 训练日志/评测 JSON 截图一闪 → 结尾页
口播：
"技术底座：昇腾 910B 训练、跨域泛化从 28.3% 提升到 69.82%，五折交叉验证、无数据泄漏，
全部评测可复现。下一步接入田间物联网相机实现自动巡检，让每个小农户
都有一位口袋里的植保专家。禾医，为农作物保驾护航。谢谢观看。"

## 录制清单核对
- [ ] 1080p/30fps，码率≥8Mbps
- [ ] 中文字幕全程
- [ ] 结果页停留≥3s，升级卡给特写
- [ ] 预先清理浏览器书签/通知
- [ ] **关闭浏览器/其他占内存程序**：R101 引擎需 ≥3GB 空闲内存，
      内存不足会静默降级到轻量模型（75%），录出来的数字不对
- [ ] **启动前确认 `.env` 已填 AMD API Key**（否则 LLM 润色静默降级为模板，
      视频里报告会失去"大模型口吻"，白录）
- [ ] 镜头 3 口播数字与当次实测一致（置信度随环境浮动，以录制当次为准）
- [ ] 语言层表述统一为“AMD LLMGateway”（AgentArts 平台部署版另录平台侧素材，
      平台上线后补一节“平台部署实录”）
