# Skill: crop_disease_decision（农作物病害诊断决策）

> 赛题3「可进化决策智能体」要求：**智能体开发及算子、MCP、Skills 等插件开发**。
> 本 Skill 是禾医智能体的**决策编排层**：它不直接产生事实，
> 而是规定"先调哪个工具、按什么顺序、什么情况下必须停下请求人工"。

---

## 元信息

| 字段 | 值 |
|---|---|
| name | `crop_disease_decision` |
| version | `1.0.0` |
| 触发场景 | 用户上传/描述作物叶片异常，询问"这是什么病、怎么治" |
| 依赖 MCP 工具 | `diagnose_leaf`、`query_knowledge_base`、`make_treatment_plan`、`check_escalation`、`submit_feedback` |
| 依赖算子 | `leaf_preprocess`（背景掩膜 + 病斑色度学特征提取） |

---

## 执行流程（严格按序）

### 第 1 步 · 感知：叶片诊断
调用 `diagnose_leaf(image)` → 得到 top-k 候选与置信度。

**分流规则**：
- top1 置信度 ≥ 0.6 → 进入第 2 步
- top1 置信度 < 0.6 → **同时呈现多个候选**，并在回答中明确说明"置信度不足，
  建议补充照片（叶背/整株）或人工复核"，**不得自行挑一个下结论**

### 第 2 步 · 取证：知识库查询（约束层）
对 top1 调用 `query_knowledge_base(disease)`。

**硬约束（防幻觉核心）**：
- 若返回 `found=false` → **必须回复"知识库未收录，无法给出处方"**，
  **严禁**凭模型自身记忆编造病名、药名、剂量
- 所有症状/病原/防治描述**只能**来自知识库返回内容

### 第 3 步 · 决策：生成处方
调用 `make_treatment_plan(disease)` → 用药/剂量/间隔/安全间隔期/预防措施。

输出时**逐条标注来源**，让用户可核对（可溯源是可信的前提）。

### 第 4 步 · 控制平面：高危升级判定
调用 `check_escalation(disease)`。

- `escalate=true` → 在回答**最上方**插入红色升级提示：
  立即联系当地植保站 / 隔离病株 / 停止自行用药，
  并明确"AI 仅做筛查，确诊需人工"
- 晚疫病、病毒病、黄龙病、枯萎病等**漏诊代价极高**的病种，
  即便置信度高也必须走这一步

### 第 5 步 · 反馈回路：闭环与进化
每次诊断生成 `record_id`，引导用户后续复诊时调用
`submit_feedback(record_id, predicted, actual, correct, note)`。

反馈数据进入 `data/feedback.jsonl`，驱动下一轮策略评审
—— 这是"可进化"的数据入口，也是本 Skill 与普通识别工具的**本质区别**。

---

## 输出格式（四段式）

1. **诊断结论**：病名（中文名 + 英文名）+ 置信度 + 候选列表
2. **处置处方**：用药名称 / 剂量 / 施药间隔 / 安全间隔期 / 注意事项
3. **农事预防**：轮作、排水、抗病品种等（来自知识库 prevention 字段）
4. **复诊与升级**：复诊时间建议；若为高危病害则含红色升级卡

---

## 约束清单（Harness Engineering · constraints）

| 约束 | 说明 |
|---|---|
| 事实来源唯一 | 药名/剂量/间隔**只能**来自知识库，禁止模型自由生成 |
| 低置信不硬判 | 置信度 < 0.6 必须呈现多候选并提示补充信息 |
| 高危必升级 | 暴发性/无特效药病害强制人工复核 |
| 溯源可核对 | 每条结论可对应到 `diseases.json` 的具体条目 |
| 反馈必留痕 | 每次诊断生成 record_id，便于复诊回流 |

---

## 为什么这是"决策"智能体而非"识别"工具

识别只输出"这是什么病"；本 Skill 输出的是
**"置信度够不够 → 证据在哪 → 怎么治 → 要不要叫人 → 结果如何回流"**
的完整决策链，且每一步都有约束与回退。这正是赛题3"可进化**决策**智能体"的落点。
